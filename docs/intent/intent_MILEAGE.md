# intent_MILEAGE — пробег не больше 400 000 км, иначе решение review

Собрано после интервью Grill Me 2026-09-24 (4 вопроса, ответы зафиксированы).
Основание: `docs/setup/code_map.md`, `docs/plan/plan_MILEAGE.md`.

## 1. Замысел

В расчёт решения по заявке добавить проверку пробега: не больше 400 000 км —
решение по LTV как сейчас; пробег выше — решение `review`. Правило меняет
**решение**, не валидацию: заявки с пробегом вне [0; 500 000] по-прежнему
получают 422 на этапе валидации и до расчёта решения не доходят.

## 2. Зачем

Сейчас решение зависит только от LTV, пробег в нём не участвует
(код: `backend/src/Domain/DecisionEngine.php`). Заявка с низким LTV получает
`approve` при любом пробеге. Правило вводит второй критерий: перепробежное
авто уходит в ручную проверку вместо автоматического одобрения.

## 3. Constraints

- Порог решения — 400 000 км. Источник: задача заказчика.
- Граница включительная: ровно 400 000 решение не понижает, понижение — строго выше (400 001). Источник: ответ в интервью.
- Перепробег — только понижающий фактор: `approve` → `review`; `review` и `reject` не меняются, `reject` не смягчается. Источник: ответ в интервью.
- Отсутствие поля `mileage` / `null` → 422, решение не считается. Источник: код: `backend/src/Domain/ApplicationValidator.php`.
- Пустая строка пробега приводится к 0 км и проходит как 0 км — поведение сохраняется. Источник: ответ в интервью.
- Валидационная граница [0; 500 000] (`vehicle.max_mileage_km`) не меняется: это граница валидации, не порог решения; при срезке до 400 000 диапазон 400 001–500 000 получал бы 422 вместо `review`. Источник: ответ в интервью; код: `backend/config/rules.php`.
- Порог 400 000 — бизнес-число в конфиге порогов, отдельное от `vehicle.max_mileage_km`. Источник: `AGENTS.md` (бизнес-числа только в `backend/config/rules.php`).
- `approved_limit` при `review` = 0 — перепробежная заявка не получает запрошенную сумму автоматически. Источник: код: `backend/src/Domain/AssessmentService.php`.

Граничные значения: 399 999 — решение по LTV; 400 000 — решение по LTV;
400 001 — `approve` → `review`.
